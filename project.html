FOV CRM 2.0

A client management app for a recruitment agency. I first built it in C# in 24 hours for my IT apprenticeship. In 2026 I rebuilt it from scratch as a secure web app, using everything I've learned since. You can try it right here.

The brief

A recruitment agency needed one place to keep their client contacts and see how each account was doing. Staff had to be able to add new clients, find existing ones quickly, update their details, and rate each company's risk as Green, Orange or Red and its status as Active or Inactive.

How I built it

  • 24 hoursto go from the brief to a working app
  • 40-hour weeksin a job with no coding in it
  • Self-taughtC# learned in my own time

I was an apprentice working full time in a role with no programming in it, so I learned C# in the evenings and at weekends. When the brief landed, I had 24 hours to propose a solution, build it and test it.

I handed in a working app: three screens connected to a real database, covering everything the brief asked for. With only 24 hours there was little time left for testing, and like most first projects it had rough edges. Looking back with more experience, I can see exactly where it could be stronger, and that's what made it worth rebuilding.

Version 2.0: what I learned, and how I used it

Supporting real business systems every day has changed how I think about software: how an app should handle what people type, why testing matters, and how data should be organised. Rather than leave the original as it was, I rebuilt it the way I'd build it today.

Version 1 (2022)

  • Searches built their database queries directly from what the user typed, which is a security risk known as SQL injection
  • Update and delete weren't fully tested in the time available, so editing didn't work reliably
  • Contact details and company details sat in separate tables that weren't linked
  • Emails weren't validated, and the phone box only blocked letters
  • Three separate windows to switch between
  • Ran only on Windows with Microsoft Access installed

Version 2.0 (2026)

  • Never trust user input. Searching is plain text matching, and anything a user types is shown as text, never run as code
  • Test what matters most. Add, edit and delete all work, with an undo button if you delete by mistake
  • Keep related data together. Each client is one record: contact, company, risk and status
  • Check data on the way in. Valid emails, UK phone numbers and no duplicate clients, with clear error messages
  • Plan for real data. Imports the agency's existing spreadsheet of 1,000 contacts, as one sheet or in the three-table layout from my original design
  • Make it easy to use. One screen with live summary counts, search across every field, filters, sortable columns and an activity log for each client
  • Make it work anywhere. Runs in any browser and on phones, supports dark mode, and exports to CSV

Why it still matters

I'm proud of version 1. I built it in 24 hours, in a language I'd taught myself, while working full time, and it did what the brief asked. It taught me how applications store and work with data, and gave me the coding foundation I now use for PowerShell scripting at work.

Rebuilding it showed me how far I've come. I now think about security, testing and data quality from the start, the same way I do when supporting clients' systems. Going back to something I built, learning from it and making it better is how I approach my work, and how I'm studying for my Microsoft certifications.
